## Today

Today opens with **Who will you be today, and for whom?**, an editable **I will**
field and **Set my focus**. Three idea cards appear below the field;
**More ideas** adds two. **Use idea** fills the field for review without saving
an intention. The person can edit it before continuing.

Typed wording, including capitals and acronyms, is preserved. A typed focus stays
typed rather than being silently replaced with a catalogue match. The next step
asks **When will you do it?**; selecting or entering a time saves the focus and
its context together. Today no longer contains the priority/interest wheels.

Saved action reminders lead the idea list when their local day arrives. Meaning
To and other grounded suggestions remain optional. A reminder is a suggestion,
not a scheduled commitment. A focus kept from Goodnight becomes an editable
prefill on the following local day and still requires confirmation and a time.

## My map and discovery

My map presents six illustrated entry points: **My why**, **Who I'm becoming**,
**What I'm growing**, **Who I show up for**, **Try something new** and
**Future me**. Existing why, priorities, interests, people and future records
remain available through these entries.

**Build an action** contains the three wheels: priority, interest and person or
place. Each wheel shows five word rows and has a separate margin for scrolling
the page. Explicit selections are applied together; an impossible combination
does not silently discard one of the person's choices. **Harder** stays within
the same action family, while **Another idea** moves to a different family.
The person can make the result today's focus or save **Remind me of this action**
for the following day.

Interest discovery offers **Close to what you love** and **Something different**,
with up to three ideas in each group. It excludes interests already on the map
and avoids repeats when **Other ideas** refreshes the groups. Passed suggestions
have a seven-day cooldown. Adding a suggestion requires an explicit choice;
browsing does not change its stage. What I'm growing leads with Into it, then
From time to time and Want to try, with All in and On pause still available.

## Night and Goodnight

Night puts the reflection on one page:

- **Did you show up?** — I did / A little / Not this time.
- **How did it feel?** — Gave me energy / Neutral / Drained me.
- **Anything worth noting?** — an optional note with short prompt starters.
- **Done** and **Skip tonight**.

Explicit energy is retained for every completion outcome, including Not this
time, and for a priority-only focus with no interest. Unknown or skipped energy
remains `null`; it is never derived from completion. The same contract applies to
the direct Night screen and Chloe's editable reflection proposal. Existing
revision checks, ownership rules and guest-import behavior remain in force. No
schema migration is needed for this correction because the database already
supports these combinations.

Priority review is occasional and based on lived focus days. A newly noticed
interest needs consent before it is added to My map. Tagging an activity on an
intention alone does not grant that consent.

For a partial or uncompleted focus, the optional obstacle section can offer six
plain reasons and a smaller next step. It is suppressed on a hard day, when the
person skips the night, and on consecutive local nights after an obstacle prompt.
The saved marker distinguishes a question being shown from an explicit answer.
Repeated stalls can draw from the new skill ladders; private reasons and counts
are not shown as judgments or included in administrator reports. Let it go
prevents a carry-forward action. Worst-case coaching requires explicit hesitation
of an eligible kind and cannot be triggered by a skipped or unanswered question.

Goodnight contains a short recap, the optional **Same focus tomorrow?** choice,
a credited thought or the existing fallback, and the closing button.
**Yes, keep it** preserves a suggestion for tomorrow; **I'll choose in the
morning** leaves that decision open. Neither choice creates tomorrow's intention.
The existing support rules continue to suppress ordinary coaching and thoughts
when a more serious support response is needed.

Chloe's prompt version is `chloe-2026-11-25-round4`. Server context now includes
the private obstacle state with explicit answer and release gates. The app owns
the visible forms, so Chloe does not repeat questions that the person already
answered or fabricate a saved reflection.

## Reproduce imports and local checks

data. The workbook importer uses Python's standard library. The PDF importer also
requires `pdfplumber` and the `pdftotext` command.

```sh
python scripts/extract-round4.py '/path/to/iwillbe-mission-library(2).xlsx'
node scripts/build-round4-seed.mjs
python scripts/extract-round4-night-library.py '/path/to/iwillbe-me-developer-pack-round4.pdf'
npm run check
npm run test:database
npm run build
```

The PDF command regenerates the current master prompt, night library JSON,
source metadata and night-library migration. Review generated changes before
committing. None of these import/build commands connects to the live database.

## Isolated Round 4 QA fixture

The [final hosted QA controller](https://iwillbe-jnfcd0fvs-snag-live.vercel.app/qa.html)
is a Preview deployment of the dedicated `qa/round4-experience` branch. Its
deployment-only configuration builds the fixture and serves
`test-results/round4-preview`; that QA configuration must not be merged into the
production branch or promoted to production. The manual review above identifies
the precise QA and feature commits it covered.

The fixture builder copies the normal `dist` export into
`test-results/round4-preview` and adds fictional local responses to that copy.
It does not alter `dist`, `vercel.json` or the production build command, and it
refuses `VERCEL_ENV=production`. The local transport and content security policy
block live Supabase, AI and other external requests. Fictional accounts,
reflections and reminders remain inside the preview's browser storage.

Build and start the preview:

```sh
npm run build
node scripts/build-round4-fixture.mjs
node scripts/serve-round4-fixture.mjs
# http://localhost:4184
```

Open **http://localhost:4184/qa.html** for the visible QA controller. Its buttons
select any of the four scenarios, switch the app viewport between 390 × 844 and
320 × 568, open Today/My map/Night/Future me, reset fictional state or move the
clock to the same evening or the following morning. Advancing the clock retains
saved records. The state panel shows local/blocked service calls, record counts
and the exact saved action, time, outcome, energy, reminders and tomorrow choice.
This allows browser review through visible controls without injecting test state
from developer tools.

Run the behavioral suite in a second terminal with an available Playwright
Chromium installation:

```sh
UI_BASE_URL=http://localhost:4184 node scripts/verify-round4.mjs
```

`PLAYWRIGHT_EXECUTABLE_PATH` or `PLAYWRIGHT_CHANNEL` may select an existing browser
installation. Screenshots are written to `test-results/round4-ui`. The suite uses
the isolated fixture; running it against the ordinary `npm run preview` export
does not supply the expected mock APIs.

| Scenario          | URL path                                          | Purpose                                             |
| ----------------- | ------------------------------------------------- | --------------------------------------------------- |
| Morning           | `/?qaScenario=morning&qaReset=1`                  | Empty Today, ideas, editable text and time          |
| Evening           | `/reflect?qaScenario=evening&qaReset=2`           | Priority-only focus, Night and Goodnight            |
| Next day          | `/?qaScenario=next-day&qaReset=3`                 | Due action reminder at the top of Today             |
