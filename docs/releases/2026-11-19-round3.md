## Behavior

- Today keeps priority and who/where together. When that combination has no
  eligible mission, it visibly clears who/where and falls back to the priority.
  Main-priority matches rank first. Easy, Normal and Stretch remain one idea.
- Eligibility uses the person's timezone, current time, weekday and saved kids'
  ages. Evening steps can be done at home; outings wait for morning. Long weekday
  variants are disabled with an explanation, without substituting another idea.
- Healthy steps rotate among seven themes. Picks, completions, positive energy,
  passes and the optional once-only night preference affect the weighting.
- Both a typed focus and an accepted suggestion first ask **When will you do it?**
  One timing choice saves the focus and plan together. The ideas disappear while
  planning and after saving; **Change focus** reopens them. Suggested steps from
  My map, Future me and Chloe use this same flow.
- Chloe introduces herself before onboarding and labels her Today messages.
  Evening choices change to now / after dinner / at bedtime. From 5 pm,
  **Check in with Chloe** is the prominent orange action, including on days
  without a focus. Both wheels have a separate strip for scrolling the page.
- Kids' ages are optional, allow multiple bands, and are asked only once,
  including when skipped. They can be supplied during onboarding or when kids
  first come up in a focus, chat or night check-in.
- Every completed night closes with a credited library thought or a reframe.
  Missing candidates, a missing AI key, quota exhaustion and provider failure
  have a saved fallback. The date shown is recorded. Only support levels 2–3
  suppress the thought; an ordinary hard day still receives one.
- My map and Me share the be.me header. The why card is more compact. Interest
  sheets contain a step, size and stage controls, and nearby interests with their
  reasons. Explore draws three suggestions from Into it interests and refreshes
  on each visit.
- Future me contains four Someday horizons, each with its own question and Add
  action. Existing future-picture data is retained but its writing boxes are
  removed. Monthly reflection uses the This year list.
- **What I've planted** appears in the Sunday review. The old Rhythms links and
  the people/saved-thoughts section are removed from Today and My map; the stored
  entries are retained.

## Weekly administrator report

`/admin` is a separate account-protected page with a weekly CSV export. It is not
linked from the participant interface. A service-managed allowlist controls
access; user-editable profile or JWT metadata cannot grant access. The public
invoker RPC calls a private definer function that checks `auth.uid()` again before
reading any participant rows. Removing the allowlist entry revokes both paths.

The explicit projection contains identity, onboarding completion/progress, focus
counts, typed versus suggested counts, completed nights, screen opens and the
last observable active day. It never returns journal text, focus wording,
reflections or conversation messages. CSV cells are escaped and spreadsheet
formula prefixes are neutralized.

Weeks run Monday to Monday in each participant's timezone. Existing usage-sharing
preferences still govern screen-open collection. Missing or earlier uninstrumented
data is labeled **Not collected**; partial periods remain distinguishable from
zero. Historical nights without a focus may be incomplete. Onboarding progress is
current; last activity is limited to the selected week's end. Malformed legacy
JSON dates, including invalid timezone offsets, cannot break the report.

Provision the intended administrator separately after the report migration using
the verified account UUID. Do not seed an email address or a production UUID in
a migration. Only the trusted service/database role can change this allowlist.

## Isolated browser preview

The normal `npm run build` exports only the product. The optional
`node scripts/build-round3-fixture.mjs` post-build step adds `/qa.html` and a local
fake service to that particular build. It refuses `VERCEL_ENV=production`.

The QA controller provides morning, evening, new account, failed night-thought API,
ordinary administrator denial and fictional administrator report scenarios. Auth,
database and function responses stay in local storage. Network interception and
a content security policy prevent calls to the real Supabase and AI services.
Only fictional names and emails are used. Resetting a scenario resets its local
data. This build is for preview only and **must never be promoted to production**.

For a hosted QA build, use a separate branch with a deployment-only build command:

```sh
npm run build && node scripts/build-round3-fixture.mjs
```

The release branch retains `npm run build` in `vercel.json`.

## Rollout and remaining product decisions

Apply the mission catalogue migration and the report migration, provision the
verified report administrator, deploy the Chloe Edge Function with its existing
authentication, and deploy the normal web export. The database changes preserve
private missions and user history and are compatible with the previous client.
Native iOS/Android binaries and live provider conversations are outside the web
fixture's coverage.

The PDF explicitly leaves four decisions open. This release does not choose them:
the tester cap (50 versus 20), global Beta versus Early access wording, a new
prompt-disclosure refusal rule, and the additional tester signup notice.

Two workbook inconsistencies are recorded in `data/round3/README.md`: `KK-02a`
is tagged as an outing, and `KK-10b` lasts 60 minutes. The selector respects those
concrete settings rather than treating them as universally suitable evening or
weekday Normal steps. The externally linked Today and Future me mockups were
unavailable; the implementation follows the written specification and existing
visual system.
